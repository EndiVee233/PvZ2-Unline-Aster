# 腾讯社交玩法移植计划

以 Aster A250 为底包。第一版先做关卡星级选择、离线好友成绩榜和阵型查看，打通从选关到通关再到查看记录的流程。随后增加友情阳光和借用植物，最后接友情转盘和可选的社区阵型数据。保留 Aster 的迷宫地图和各玩家存档，沿用 Aster 的界面布局。

## APK 对照

- 工作区根目录的 `植物大战僵尸2腾讯社交版.apk` 为 35,280,188 字节。Manifest 包名 `com.tencent.pvz`，versionName `1.0.141`，versionCode `7`，仅含 armeabi-v7a。SHA-256 为 `c8122d6fd6e840c140bd23c8a541a927a90049ed2d94e58fd8ff047d81b4bf82`。[社交版 APK](../../植物大战僵尸2腾讯社交版.apk)
- 本地解开 `assets/main.rsb.smf` 后，得到 v4 RSB，包含 274 个组、603 个组内条目。已读取资源清单、中文文本以及埃及第 1、2 天、功能定义、关卡模块和 LiveConfig 的 RTON。社交相关图集为 `UI_Friend_640`、`UI_Rank_640`、`UI_Lottery_640`，另有三个转盘动画。A250 的 `uicommon.rsb.smf` 有 `UI_Lottery_1536` 和转盘动画组。检查过的 A250 内包 `init`、`dynamic`、`egypt`、`uiactive`、`uicommon` 未找到好友及排行专用组。[社交版 RSG 索引](../work/tencent-social-audit/files.txt)
- 社交版 `libGameSource.so` 可定位 `RankWidget`、`FriendListView`、`FriendSunEvent`、`BorrowPlantUI`、`BorrowPlantWidget`、`BorrowPlantFlow` 和 `LotteryUI`。A250 的 `libSrc.so` 仍有 `S2C_GameRankList`、`S2C_BorrowedPlantList` 等名字和借用按钮的贴图标识，抽样搜索未找到上述完整 UI 类名。移植前先跟踪 Aster 的调用点和工厂注册，验证能否接本地数据，再决定是否新建对应控件。包内也有腾讯平台组件，离线流程使用 Aster 的本地数据源。
- A250 的埃及第 1、2 天各自有现成的星级条件，并拥有不同于社交版的教程模块。两版的 `LEVELMODULES.RTON` 都把埃及、海盗和西部的 `StarChallengeUnlockLevel` 分别指到 `egypt11`、`pirate10`、`cowboy10`，A250 用数组保存这些关卡别名。接选关 UI 时传入当前关卡的原生星级选项，由 Aster 执行关卡与发奖。恢复转盘入口前核对它与签到的位置和点击路径。旧版 Aster 曾同时关闭转盘入口的绘制、命中和点击，仅显示图标无法恢复功能。[地图入口记录](recovery/地图入口移除结果.md)

## 分期实施

### 1. 星级选择、离线好友成绩榜和阵型

1. 用埃及第 1、2 天验证地图选关、四档条件和进入关卡。分别验证主线通关和获得三星罐头两个入口。订阅 Aster 的正式胜利流程，在清除棋盘前取一次场上阵型和用时。败北、退出、重试只丢弃本局记录，较慢的通关保留旧最佳成绩。用同一个计时结果驱动战斗 HUD、通关记录和排行榜。
2. 显式定义计时起点和结算点。建议从开始战斗计到胜利判定，排除选卡、暂停、过场和结算。以游戏时钟为候选，实测倍速、暂停、重试和后台运行后锁定口径。友情支援或其他会显著改变成绩的规则随记录保存，排行只对比同一口径。
3. 通关时把阵型随最佳成绩保存到当前玩家数据。点地图关卡先打开选关页。左侧按档位列出好友成绩，选中好友后可进入该关的专用预览棋盘，由原生引擎按格位和阶数放置植物，上下层植物沿用 Aster 的实际占位规则。预览期间屏蔽对局和输入，退出回地图。已有通关进度可用于判断解锁，缺少历史计时或阵型时显示空状态。
4. 随包提供一份版本化的离线好友 JSON，同一文件包含好友及逐关记录。实现一个不依赖网络的加载器，接受已知头像资源标识、稳定的植物别名和关卡别名。照片 2 的 `GridX`、`GridY`、`Level`、`PlantTypes` 可作为导入字段的参考，导入时明确坐标原点和堆叠含义。Aster 的 PVP 预设已有大小、目录、植物别名和坐标校验，可借用校验思路，冒险关卡采用自己的关卡规则。[PVP 预设读取](../src/bootstrap-extra/com/popcap/pvz2cthd/PvpPresetDocument.java)

### 2. 友情阳光与借用植物

1. 好友页从同一目录读取离线好友，按当前玩家生成送礼和待领记录。战斗中从已有阳光「＋」入口进入友情阳光页，保留购买阳光。校验仍在当前对局且账号一致后再加阳光，并同步消耗该礼物；重复点击、退出重进或回读战斗时都按同一领取记录去重。
2. 首轮在允许自由选卡的普通冒险关卡复现借用。候选用好友的最强植物，申请绑定当前局和当前账号，战斗中途掉落借用卡，沿用真实种植费用和落点检查。核对战斗内借用按钮与战前入口的关系，两个入口如都启用则共享本局借用记录。重开、退出、胜负结算和切换账号时清掉临时授权，借用植物不写入拥有列表。传送带、预置阵型、无尽、PVP 等模式先沿用各自的规则。
3. 在实现次数和冷却前核对社交版中送礼、领取、借用的本地路径。原包字符串只证明存在上限。若数值由旧服务下发，Aster 的离线值用独立配置固定，并在实测表中明确。

### 3. 友情转盘与可选社区更新

1. 用 Aster 的高分辨率界面和本地发奖入口搭建友情转盘。以已核实的 10 点档为对照，先核对奖位映射、权重、重复奖励和累计里程碑。旧包文本能列出奖励类型和部分数额，无法单独证明概率。消耗、开奖和累计发奖按同一账号的一次操作持久化，测试点按过快、切后台、强退和重启。
2. 本地榜单稳定后，再提供可选的 GitHub 数据更新与自主投稿。离线始终有随包数据；更新只提供只读好友资料和阵型，保留上次有效版本并标明社区投稿来源。投稿导出只包含玩家选定的一条成绩和阵型。客户端本地成绩和投稿以来源字段区分，便于理解排行数据。
3. 额外抽奖次数作为好友赠礼的一种，与友情值消费分别记账，接入同一离线好友数据和领取流程。实际额度待旧版证据或离线配置确定。阵型分享可通过只读预览和导出实现，获得新植物后分享到朋友圈属于可选项。

## 存档与验收

- 账号用 Aster 的持久玩家标识，关卡用世界、关卡别名和星级档位组合，附计时规则版本。只读好友文件可以共用。个人最佳、赠领记录、借用限额与抽奖账本各自归属当前账号。参考签到的当前账号复核与 PVP 驻防按玩家隔离、校验和原子落盘的实现。[签到实现](../src/daily-sign-in/daily_sign_in.cpp) · [驻防存档](../src/offline-pvp/garrison_storage.h)
- 第一阶段的验收先在 WSA ARM32 使用 WSA USER 验证。检查无星档能进战、三星解锁及挑战条件、首胜写榜、更快成绩覆盖、较慢成绩保留旧记录，以及退出和重启后的最佳记录。用隔离测试档核对两个账号切换和两个关卡的数据。回归地图签到、缩放、植物探险及两种无尽，确认入口和进度各自正常。测试前备份并在结束后逐文件校验回档。
- 后续阶段再验证同一礼物领取一次、重开后不重领、支援卡能打出且不会进入普通植物拥有列表，以及榜单在坏文件、断网和未知植物时可继续使用。两个构建同步共享代码，WSA 仅验收 ARM32。

### WSA 调试包

构建脚本的 `--wsa-test --wsa-battle-tools` 参数生成单独的 ARM32 调试包，使用 WSA 已提取的资源。进入埃及第 1 天或第 2 天的实际战斗后，可从工作区运行下面的命令。每次启动新一局都清除先前的命令。暂停期间停止执行，作战结束后持续清场自动失效。

```powershell
python scripts/wsa_battle_tools.py clear
python scripts/wsa_battle_tools.py sweep
python scripts/wsa_battle_tools.py stop
```

`clear` 调用一次原生清场逻辑，`sweep` 每游戏秒处理一批，`stop` 取消持续清场。正常波次、胜负判定和奖励仍由关卡处理。用过这些命令的成绩写入独立测试记录，常规个人最佳读取正常记录。测试前备份存档，结束后回档。

WSA ARM32 已验证单次命令被读取，持续清场使埃及第 1 天按原生流程获得第一星。1 分 26.270 秒的成绩只出现在调试记录里。模拟检查还覆盖暂停、停止、重试和非目标关卡。

### 1.7.5 原生控件接入

- 用户提供的《1.7.5 新建界面 / 弹窗 实战记录》和《路线 1：危险房页面初始化对齐施工清单》用于核对控件创建、挂载和销毁。Aster 底包反汇编确认，`0x403988` 创建并挂载原生消息框，`0x403828` 可挂载传入的完整 Dialog，`0x7F25EC` 注册按钮委托。挂载顺序为 WidgetManager 登记、重排、附着，再调用管理器的最后一步更新。
- 好友选关页从地图拦截正常进关，原生控件应由地图一侧持有，退出或进关前通过原生关闭流程摘除。关卡内预览再接自己的返回控件。危险房页面是无尽关卡加载期的对象，初始化和所有权与好友页面不同。
- 选关面板使用 Aster 的原生 Dialog、高清字体和按钮。按钮回调把操作交给下一次引擎更新执行，切档时留在同一个 Dialog，进关前由原生关闭流程摘除。Android 侧仍负责读取离线成绩文件和处理阵型预览的返回条。
- A262 直接在 WidgetManager 挂载选关 Dialog，使用原生模态输入和安全销毁流程。这样从好友棋盘回地图后再次打开选关页，地图仍会绘制在弹窗下。WSA USER 已复测这条往返路径。
- A265 复用 Aster 1536 图集中的弹窗红叉、星级奖励缎带和星形、页签和绿按钮。已获得的星显示为金色，未获得的星显示为紫色。锁定的挑战显示灰色控件，仍可点击查看解锁条件。
- A265 ARM32 已在 WSA USER 核对选关页显示。埃及第 2 天的离线阵型显示四株植物，返回地图后可再次选关，并从「第二星」进入带花坛、植物损失上限和小推车要求的原生挑战。测试后的 68 个存档文件已恢复并逐一校验。

### 星级自选接入调查

- Aster 的原生关卡加载先检查世界解锁与当前节点的主线通关状态，并从关卡模块读取可用挑战档。通过门槛后，它从低到高挑选第一个尚未领取的星级。重打已经达成的档位因此需要明确指定索引，并继续使用该档原生的挑战条件。
- 埃及第 1、2 天各有三个挑战档，条件组合不同。启动关卡时传入的最后一个整数用于关卡随机种子。自选需要把本次所选档位和当前账号、关卡绑定，在加载时取用。领取过的星仍由原生发奖流程判定。
- A265 离线菜单按本关主线通关状态开放三档挑战。选中档位后，棋盘加载从本关的原生目标表读取该档位，重玩沿用选择，返回地图后清除本次选择。奖励继续使用引擎本身的判定。
